2실행 모델 — API + CLI 혼합

스테이지마다 실행기를 골라 끼운다. CliRole이 기존 Role.run(prompt, response_format=Model) 시그니처를 흉내 내 fallback 체인 항목으로 들어가므로, 오케스트레이터는 그대로 두고 config로만 지정한다. 원칙: 걸러내는 앞단=API, 사고하는 뒷단=CLI.

스테이지실행기이유

CLI 스테이지는 캐싱·토큰 비용계측을 잃음 → 그 단계는 run-log로 대체 계측. 실행기 선택은 스테이지별 config라 언제든 이동 가능.

5지식층 — 사례 기반 금융 메모리

핵심 능력: "과거에 이 조건이 만들어졌을 때 이후 어떤 순서로 전개됐는가"를 기억하고 현재와 대조. 규칙(if/then)만으론 부족 — 시간 인과 시퀀스가 필요. 지식을 3층으로 분리한다.

① 개념 지식변하지 않는 원리·메커니즘: 공급 조절엔 시차 · 수요↑→재고↓→가격↑ · 가격↑→수익성↑→CAPEX↑→(시차)공급과잉
+
② 사례 지식 (시간 인과 그래프)과거 에피소드를 시퀀스로 저장 — 아래 띠
→
③ 현재 매칭지금 관측이 그 시퀀스의 몇 단계인지 다중홉 검색으로 대조 → 다음 전개 예측
수요급증 → 재고감소 → 가격상승 → 수익성개선 → CAPEX확대 → (시차) → 공급과잉 → 가격하락   ← 현재 위치를 여기서 찾는다
참고 아키텍처 (외부, 검증함) — ② 사례 지식의 표현 = temporal knowledge graph:
· OpenAI "Temporal Agents with Knowledge Graphs" — 비정형 텍스트→엔티티·관계 추출 + 시간충돌 해소로 그래프 구축, 다중홉 검색으로 여러 사실을 인과 사슬로 연결 (타임라인·변화추적·반사실). 인과 시퀀스에 구조적 최적.
· Graphiti / Zep (OSS 에이전트 메모리) — bitemporal: 사건시각(T)+관측시각(T′) 분리.
정렬: 우리 SectorCard.ts(사건)+ingested_at(관측)이 이미 bitemporal, thesis valid_from+input_snapshot이 forward-capture → 그 위에 시간그래프 얹기 자연스러움.
