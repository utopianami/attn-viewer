## 0. 현재 vs 목표

- 현재: 12h 수집분 → 필터 → 합성(주장 2) → 검증 → 조립. **재료가 창 안에 갇힘** → 주장이
  "관측 나열+조건부 단서"에 머물고, 출력이 주장 카드라 완결된 논증 글이 아님.
- 목표: 12h 재료는 **문제 제기와 뼈대**를 만들고, 논증 완성에 필요한 입력값은
  **역방향으로 추가 조사**해서 채운 뒤, 공대인 틀의 **완결 글(article)** 을 낸다.

## 1. 공대인 사고의 틀 (원문에서 추출 — compose 프롬프트의 헌법)

1. **한 줄 요약** = 결론 선언 + "진짜 질문" 재정의(이분법 시나리오: −15%냐 −30%냐) + 방법론 선언(근거/가정 구분).
2. **자(尺) 정정** — 순환논리 제거("가격 알려고 매출 보면 순환"), 지배 방정식 1개 선언
   (예: 수급 갭 = 비트 수요 증가율 − 비트 공급 증가율).
3. **비대칭 인식** — 계산 가능한 것(공급)은 고정, 추정만 되는 것(수요)은 **손익분기 역산**으로 문턱화.
4. **바텀업 검산** — 공식값을 독립 방법으로 재현 → 재현되면 연장 자격. 실패하면 연장 금지.
5. **하위 분해** — 병목을 제품(HBM/일반)·등급(고급/저가)으로 가르고, 간과 축(CXMT 등) 명시.
6. **입력값 표** — 모든 입력에 〔근거: 출처〕/〔가정〕/〔계산〕 라벨 + "시뮬레이션" 주의문.
7. **반전 섹션** — "대부분이 놓치는 것": 지배 방정식에 시나리오 대입(1.18×0.85−1=+0.3%), 재무 귀결(계약 floor·선수금·마진).
8. **관찰 신호** — 예측 대신 선행 신호 N개, **각각 현재 상태 판정**("지금은 해당 없음/바닥/증액").
9. **메타 질문 + 겸손** — "이번엔 다르다는 대개 틀렸다", 한계·열린 변수 명시,
   "정확한 수치 맞히기가 아니라 틀을 쥐는 것".
- 문체: 단문·구어체 리듬("문제는 미래다"), 계산 명시, 짧은 문단.

## 2. 신규 스테이지 (기존 파이프라인 뒤에 추가)

기존 raw→f1→f2→f3→deepen→synth→verify→reflect→assemble 은 유지(검증된 12h 재료 생산).
그 출력을 입력으로:

```
[A] draft   (CLI)  12h 재료(클러스터·앵커·주장·반증·과거사례)에서
                   → 핵심 질문 1개 + 지배 방정식 + 뼈대(섹션별 논지)
                   + research_questions[] (질문·왜 필요·기대 형태·검색 힌트)
[B] research(CLI+웹) 질문별 claude -p --tools "WebSearch,WebFetch" 조사
                   → ResearchFinding[] (답·수치·출처 URL·발행시점·근거/가정 라벨)
                   코드 게이트: URL 없는 수치 → '가정' 강등. 질문당 타임아웃.
[C] compose (CLI)  뼈대 + 12h 검증재료 + 리서치 결과 → 공대인 틀 완결 글(markdown)
                   §1 프레임을 프롬프트 헌법으로 주입. 입력값 표 필수.
[D] audit   (코드+API) 본문 수치 스윕: (앵커 ∪ 12h evidence 수치 ∪ 리서치 수치)와
                   abs+3% 대조. 미확인 수치는 기각이 아니라 본문에 ⚠미확인 각주 주입
                   (완결 글은 기각하면 아무것도 안 남음 — 투명 표기로 전환).
                   시점 검증: 리서치 출처 발행일 > effective_now 금지(미래 없음),
                   look-ahead 반대로 리서치는 최신 허용.
```

## 3. 계약 추가 (report_contracts.py — additive)

- `ResearchQuestion {qid, question, why_needed, expected_form, search_hint}`
- `ResearchFinding {qid, answer, numbers[], sources[{url,title,published}], label: 근거|가정, error?}`
- `Report.article: str` (markdown 완결 글) + `Report.article_meta {skeleton, questions, findings_summary, unverified_numbers[]}`
- 기존 claims/overview/finalOpinion 유지 — article은 additive (뷰어 폴백 안전).

## 4. 불변식 (기존 유지 + 신규)

- never-raise/never-hang: [A][C] 30분, [B] 전체 40분·질문당 8분, 실패 시 **기존 리포트로 강등**
  (article 없이 저장 — 지금과 동일 출력). 리서치 0건이어도 compose는 12h 재료만으로 진행하되
  글 서두에 "추가 조사 실패 — 12h 재료만" 명시.
- 날조 차단: compose가 쓸 수 있는 수치 = 앵커 + 12h evidence + ResearchFinding.numbers.
  그 외는 audit이 ⚠미확인 각주. 리서치 수치는 URL 실존(형식 검증)이어야 '근거' 라벨.
- 결론 불변식 완화: article의 결론은 검증 주장이 아니라 **시나리오+문턱+관찰신호** 형태
  (공대인 틀 자체가 단정 대신 조건부 구조). finalOpinion은 기존 로직 유지.
- 제목: article의 한 줄 요약에서 헤드라인 추출(기존 _headline보다 우선, 실패 시 폴백).
