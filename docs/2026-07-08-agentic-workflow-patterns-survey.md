## 1. 검증·자기교정 (REFLECT·AUDIT 직결)

### 1-1. 역할 재제시(role relabeling) — 최우선 실험 후보 [高신뢰, 3-0]

- 검증 실패한 claim을 같은 컨텍스트에서 "다시 검토하라"고 시키지 말 것. **별도 턴에서 외부 역할**(user 메시지·tool 응답·system `<memory>` 블록)로 byte-동일 claim을 재제시해 감사시키면 교정률이 크게 오른다.
- 수치: 자기불신 프롬프트 교정률 0~23.3% (일부 베이스라인보다 악화) vs `<memory>` 역할 재제시 70%, 전반 +23~93%p (13개 모델-도메인 셀 중 10개 p<0.001).
- 원인: 검증 능력 부족이 아니라 **자기 추론을 이산 객체로 지목하지 못하는 것**(addressability).
- 출처: arXiv:2606.05976 "The Self-Correction Illusion" (2026-06 프리프린트).
- 적용: REFLECT·AUDIT 프롬프트/턴 구조 변경만 — **난이도 낮음**.
- ⚠ 주의: 도메인이 수학·논리 (금융 외삽 미검증 → A/B 1순위). "이 답은 의심스럽다" 프레이밍을 넣으면 옳은 claim까지 뒤집는 과교정 70%까지 — **중립적 재제시** 필수. 같은 논문의 "Self-Refine·Reflexion·CoVe 재현 실패" 주장은 검증 기각(0-3) — 인용 금지.

### 1-2. LLM 심판의 동의 편향 — AUDIT 단독 의존 금지 [高신뢰, 3-0]

- 14개 최신 LLM 심판 실험: 옳은 출력 인식(TPR) 96%+ / **잘못된 출력 탐지(TNR) 대체로 25% 미만** — "틀린 걸 틀렸다"고 말하는 능력이 구조적으로 약함.
- 적용: 규칙 기반 게이트(숫자·시점·지시어)는 유지. LLM 의존 게이트(근거성)·AUDIT에는 규칙 체크 보강 또는 **"틀렸다고 가정하고 반증을 찾아라" 역할 분리**.
- 출처: NUS "Beyond Consensus" (2025-10). ⚠ TNR<25% 수치는 코드 피드백 단일 도메인 측정 — 방향만 신뢰, 수치 외삽 주의.

### 1-3. REFLECT 적응형 종료·파라미터화 [高신뢰, 3-0]

- gpt-researcher Deep Research: depth(기본 2)·breadth(기본 4) 파라미터형 트리 재귀 + 동시 실행 (1회 ~5분, ~$0.4 — 자체 추정).
- 적응형 조기 종료: 판정 정확도를 시변 Beta-Binomial로 모델링, KS 통계량 D<0.05 2라운드 연속이면 중단 — 10라운드 대신 4라운드 종료에 정확도 손실 −0.60% (2025-10 프리프린트, 독립 재현 없음).
- 적용: REFLECT "고정 2회" → 수렴하면 조기 종료, 안 하면 depth 추가. 난이도 중간.

### 1-4. claim당 독립 소스 수 하한 [中신뢰 — 가정 기반]

- gpt-researcher가 "20개+ 소스 집계"를 편향 완화책으로 채택 (v3.5.1 활성 유지). 단 "소스 수↑→오류↓"는 명시적 **가정**이며 정량 근거 없음 — 채택 시 하한값 A/B 검증 권장.
- 참고: gpt-researcher 구조(planner/executor/publisher)는 우리 PLAN→병렬 수집→조립과 동형 — 설계가 업계 표준과 일치한다는 방증.

## 2. 메모리·학습

### 2-1. 아웃컴 기반 반성 메모리 [高신뢰, 3-0 — 단 난이도 높음]

- TradingAgents **공식 코드 구현체**: 실현 수익(vs SPY)을 회수해 `reflect_and_remember()`로 교훈을 FinancialSituationMemory에 적재, 다음 실행에 주입. (v1 논문에는 없음 — 인용은 코드 기준으로.)
- 적용: 파이프라인 뒤 비동기 "결과 회수 → 반성 → 메모리 적재" + 앞 "관련 교훈 검색 → PLAN·RISK에 주입".
- ⚠ QA 도메인에서 "실현 결과"의 정의(주가 적중·사실 확정·사용자 피드백)와 회수 시점 설계가 선행 과제. 효과 정량치 없음.

### 2-2. 크로스세션 노트 주입 [高신뢰, 3-0 — 난이도 낮음~중간]

- LangAlpha(ginlix-ai, "Claude Code for Investing", v2026.06.27, ~1.5k stars): 워크스페이스 노트(agent.md)를 미들웨어가 **모든 모델 호출의 시스템 프롬프트에 주입** (`WorkspaceContextMiddleware`, 8KB 상한 큐레이션 노트: 목표·핵심 발견·인덱스). 코드 검증 완료.
- 적용: 질문별 핵심 결론·미해결 이슈를 노트로 누적 → 다음 질문 시 주입. 반복 종목/테마 질문에서 재조사 비용 절감.
- ⚠ README "full context"는 과장 — 실제 8KB 큐레이션. "무엇을 남길지" 규칙 설계가 핵심.

- 적용: 시세 시계열·재무제표 처리 경로 — 컨텍스트 팽창·토큰 낭비 절감. 난이도 중간~높음(샌드박스 인프라).

## 4. 실행 효율·구조

### 4-1. 난이도별 예산 배분 (adaptive computation) [高신뢰, 3-0]

- Anthropic 프로덕션: 난이도별 노력 규칙을 **프롬프트에 명시 내장** — 단순 사실확인 = 에이전트 1·툴콜 3-10회 / 직접 비교 = 서브에이전트 2-4·각 10-15회 / 복잡 리서치 = 10개+.
- open_deep_research: 역할 4종(요약/리서치/압축/최종)에 **서로 다른 모델·토큰 예산** (요약만 저비용 모델).
- 적용: 유형 라우팅 + 스테이지별 모델 티어의 직접 근거. 스킵 기준은 비용이 아닌 **품질 영향**으로 설계 (사용자 원칙 정합).

### 4-2. 감독자 동적 병렬성 [高신뢰 — 교란 주의]

- Anthropic: 리드(Opus) + 서브(Sonnet) 구조가 단일 Opus 대비 내부 평가 90.2% 우수. ⚠ 성능 분산의 ~80%가 토큰 사용량(~15배)으로 설명 — 아키텍처 순수 효과로 읽지 말 것. breadth-first 질문 한정.
- open_deep_research: 감독자가 think_tool로 하위 주제 위임 + asyncio.gather 병렬, 동시성 상한, "언제 병렬화할지" 휴리스틱을 프롬프트에 내장.
- 적용: 고정 3채널 수집 → PLAN이 하위질문별 수집 유닛·채널을 동적 결정. 의존성 많은 질문엔 부적합(Anthropic 명시).

### 4-3. 증거수집 계층화 — 근접 우선 탐색 [高신뢰, 배포 제품]

- OpenBB Copilot: **명시적 컨텍스트(사용자 추가) → 대시보드(현재 화면) → 글로벌(워크스페이스 검색)** 3계층 우선순위 — 애널리스트 작업 순서 모방. 2025-02 설계가 2026 현행 제품 문서에서 확인.
- 적용: "보유 데이터(섹터 대시보드·kg.db·직전 답변) → 캐시된 수집물 → 외부 웹 검색" 순서. 외부 검색 비용·지연 절감. 난이도 낮음~중간.

### 4-4. 스트리밍 중간 결과 + 미드런 스티어링 [高신뢰 — 기능 존재 확인]

- LangAlpha: 실행 중 사용자가 후속 메시지로 메인/서브에이전트를 완료 대기 없이 방향 수정 (스텝 경계 소비).
- 적용: PLAN 결과 노출 → 사용자 수정 허용 지점 — 잘못된 분해로 파이프라인 전체가 낭비되는 것을 조기 차단. 난이도 높음(인터럽트 가능 구조 재편).
