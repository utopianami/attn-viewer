QA 엔진 — 에이전틱 워크플로우 개선 계획

2026-07-08 (v2.2 — 코덱스 리뷰 R1·R2 반영) · plan — 확정되는 대로 제자리 갱신 · 현행 파이프라인: workflow-review.html · 리뷰: R1→응답→R2 (APPROVE w/ nits)→응답
본질은 에이전틱 워크플로우 자체의 품질 개선이다. 질문 유형별 라우팅은 그 일부(§6). 근거는 서베이 2회 + dexter 코드 분석 (§1), 본체는 §2 개선 백로그와 §5 개선 후 전체 그림, §3 하지 말 것 / §4 지키는 것, §7 로드맵, §8 결정 현황 (D1~D3 승인 완료 2026-07-09).

0왜 바꾸나

  • 모든 질문이 같은 길을 걷는다 — 숫자 하나 묻는 질문과 판단 질문이 똑같은 풀코스(약 2분 30초). 분류(tier)는 하면서 분기에 안 씀.
  • 루프가 고정 2회·백지 재시작 — REFLECT 재조사가 수렴 여부와 무관하게 최대 2회 고정이고, 실패 사유를 다음 라운드에 구조적으로 전달하지 않음.
  • 질문 간 학습이 없다 — 어제 조사한 종목을 오늘 또 물어도 처음부터. 답이 맞았는지 틀렸는지 돌아보는 장치도 없음.
  • 긴 파이프라인의 정보 유실 — 초반 수집한 증거 세부가 후반(종합·감사)까지 온전히 전달된다는 보장이 스키마 계약뿐.

1근거 — 서베이 2회 + dexter 코드 분석

1차: 금융 repo 서베이 · dexter 심층 분석 · 2차: 워크플로우 패턴 서베이 — 전부 2026-07-08, 적대 검증 통과분만 인용

dexter (⭐27k, ai-hedge-fund 저자 신작) — 가장 중요한 참고

v1이 우리 엔진과 같은 구조(계획→태스크 실행→완료 검증)였고, 저자가 두 달 만에 버렸다 — 코드로 직접 확인

  • v2 = Claude Code식 단일 자율 루프: 모델이 매 턴 도구를 고르고, 도구 호출 없는 응답 = 최종 답. 제어는 구조가 아니라 가드레일 — 반복 상한 10회, 도구별 소프트 리밋(차단 대신 경고 주입), 4단 계단식 컨텍스트 압축, 격리 서브에이전트(타입별 프롬프트·도구·예산 번들).
  • 단, dexter에는 우리의 CALC·검증 게이트·claim table·RISK가 없다 — 숫자를 LLM 산술+체크리스트로 처리. 이건 dexter의 약점이고 우리의 경쟁 우위 (§4).
  • 결론: 전면 자율화가 아니라, 고정 파이프라인의 "루프 부분"에 dexter의 가드레일 기법을 이식하는 게 우리 경로.

서베이 2회 요약

  • 1차 (금융 repo 22소스): 질문 유형 라우팅을 제대로 구현한 곳 거의 없음. 실전 공통 패턴 = 블록 레지스트리 + 고정 뼈대(조립→계산→검증) + 멤버십만 가변. 반면교사: LangAlpha는 분류기를 만들고 분기에 안 씀 (우리 tier와 같은 상태).
  • 2차 (워크플로우 패턴 23소스): ① "네 추론을 검토하라"식 자기교정은 거의 작동 안 함(0~23%) — 실패 claim을 외부 역할로 재제시하면 +23~93%p. ② LLM 심판은 틀린 걸 못 잡는 동의 편향(TNR<25%). ③ 컨텍스트 유실 방지 패턴이 3개 독립 시스템(TradingAgents·Anthropic·open_deep_research)에서 수렴. ④ 다라운드 debate는 검증 실패 — 우리 이중 DA가 이미 효과 흡수.

2개선 백로그 — 4축

우선순위: P1 바로 착수 후보 · P2 다음 사이클 · P3 별도 설계 필요. 근거 라벨: 대부분은 "구현 패턴 확인"(남이 실전에서 쓰는 걸 확인)이지 "효과 실증"(정량 효과 측정)이 아님 — 실증된 것은 A1(도메인 외)·A5(프리프린트)뿐. 그래서 전 항목 공통: 효과는 평가 하네스(C1)로 측정하며 채택, 실험은 한 번에 하나씩.

3하지 말 것 (안티패턴 — 검증 결과)

항목근거

4지키는 것 — 경쟁 우위 불변식

  • 숫자는 CALC(코드 계산)로만 — 조사한 시스템 대부분(dexter 포함)에 없는 우위. 어떤 개선에서도 LLM 산술 경로를 만들지 않는다.
  • claim table + 검증 게이트 + REFLECT 재조사 — 재조사 게이트는 조사 대상 대부분에 없는 강점. 구조는 유지하고 루프의 "질"(A1~A5)만 개선.
  • 이중 블라인드 DA — 이종 2모델 앙상블 효과의 원천. debate 미채택의 근거이기도 함.
  • 고정 뼈대(조립→계산→검증) — 1차 서베이의 전 활성 시스템이 택한 보수성. 블록 조합이 와도 이 스파인은 플래너가 못 바꾼다.

설계 보강 — 코덱스 R1 누락 지적 반영

  • 오분류 처리: TRIAGE 분류에 confidence 필드 추가, 낮으면 abstain → 풀코스 프로필 (현행 TriageResult는 route/fresh뿐이라 계약 확장 필요).
  • tier와 question_type의 우선순위: tier(0~4)는 안전 제어(tier4 차단·tier3 RISK·G2/G4)로 유지하고 항상 우선, question_type은 폭 제어(수집 범위·모델 티어·라운드 한도)만 — 충돌 시 tier 승.
  • RISK lite 판정 계약 (R2 반영): TriageResult에 requires_countercase 필드 추가 — 유형 분류와 같은 콜에서 "원인론·시장영향·전망 요구" 판정. PLAN은 false→true 방향으로만 덮어쓰기(승급 전용 원칙). tier 3은 필드와 무관하게 RISK 강제.
  • never-raise 보존: 프로필이 스테이지를 생략해도 skipped 패킷을 fan-in에 발신 — 기존 배리어·상태 의미(skipped/degraded/error) 불변.
  • 가시성: 선택된 프로필·생략 사유를 layer로 노출 (LAYER_NAMES 고정 어휘라 plan layer에 포함하는 형태 우선 검토) — 침묵 저하 금지 원칙 연장.
  • 승급 기록: PLAN 승급 시 사유를 meta에 남기고, 승급이 바꿀 수 있는 필드 범위를 제한 (비용 폭주 방지).
  • 테스트 매트릭스: 5유형 × 핵심 불변식(숫자는 CALC만·skipped 패킷 발신·round 관통) 회귀 테스트를 스펙에 포함.
