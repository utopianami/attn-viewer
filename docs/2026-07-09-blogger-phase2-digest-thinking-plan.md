# 블로거 2차 계획 — 다이제스트 피드 + 사고 추출 (2026-07-09)

- 목적: ① 모든 글을 매번 볼 수 없다 → 읽어야 할 글이 떠오르는 피드 ② 블로거의 사고를 뽑아 chat(QA 엔진)에서 활용.
- 1차(탭·레지스트리·백필·새 글 감지)는 완료 — `docs/2026-07-08-blogger-tab-phase1-design.md`.
- 실측 전제: 15개 블로그에서 하루 10~40편, 절반은 한 줄 메모("ㅋㅋㅋ" 등), 진짜 읽을 글은 하루 5~10편.
  → "잘 보이게"의 본질 = 이 5~10편을 골라 올리고 나머지를 가라앉히는 것.

## 뼈대: 파이프라인 하나, 출구 둘

```
새 글 → ① 분류(triage) → ② 글별 분석
                              ├→ 다이제스트 카드 → 피드   (매번 다 못 본다 해결)
                              └→ 사고 기록 축적 → 블로거 설계도 → chat 주입 (사고 활용)
```

- 같은 LLM 호출의 두 얼굴 — 비용이 겹치지 않는다.
- 피드를 매일 보는 것 자체가 "사고 추출이 글을 제대로 읽었나"의 상시 검증이 된다.

## Part A — 다이제스트 피드

1. **분류(triage)**: 저렴한 모델로 글마다 하나 — `추론글`(논지·예측·판단) / `정보전달`(뉴스 정리) / `짧은메모` / `잡담`.
   잡담·짧은메모는 피드에서 접어둔다(펼치면 보임).
2. **다이제스트 카드** (추론글·정보전달만):
   - 한 줄 주장 — 제목이 아니라 "그래서 뭐라는 글인가"
   - 근거 2~3개, 관련 종목·테마
   - **뷰 신호**: 기존 논지 반복 / 새 주장 / **생각을 바꾼 글** — 마지막이 가장 귀한 신호, 뱃지로 강조
3. **테마 묶기**: 같은 날 여러 블로거가 같은 테마를 쓰면 한 묶음 —
   "3명이 동시에 이 얘기"는 그 자체가 중요도 신호.
4. **UI**: 블로거 탭 첫 화면을 "브리핑"으로 — 날짜별 그룹, 중요 글 위로, 테마 묶음, 읽음 표시.
   (나중) 메모리 섹터 전광판 이벤트 카드와 연결 — 섹터 테마와 겹치는 글.
5. **주기**: 새 글 감지(30분)마다 즉시 다이제스트 생성 (글 수가 적어 배치와 비용 차이 미미, 피드 항상 최신).

## Part B — 사고 추출 → chat 활용

원칙(1차 브레인스토밍 합의): 추론글만 골라 / 뾰족한 질문 세트 / 시간순 연쇄에서 갱신 패턴 /
블로거 간 대조 집계(구별되는 것만) / holdout("본인 글 맞히기") 검증 / 주입 전후 A/B.

1. **사고 기록** (추론글만, 상위 모델): 글마다 구조화 추출 —
   계기 / 결론 전에 확인한 것 / 좁혀간 순서 / 검토·기각한 대안과 이유 / 유보 지점 /
   "이게 나오면 생각 바꾼다" 조건 / 결론 유형 / 관련 종목·테마.
   저장: `corpus/naver/<blogId>/analysis/<articleId>.json`.
   ★ 질문 세트는 블로거 2~3명 × 20~30편으로 시작, 탭에서 글 옆에 띄워 눈으로 확인하며 반복 튜닝.
   여기가 승부처 — 처음부터 대량으로 돌리지 않는다.
2. **백필**: 질문 세트 안정 후 최신 글→과거. 추론글(체감 30~50%)만 상위 모델 — 분류가 비용 필터.
3. **연쇄·설계도**: 같은 테마 글 시간순 묶음에서 "언제 무엇 때문에 생각을 바꾸나" 추출 →
   블로거 간 대조로 구별되는 절차만 남긴 설계도(항목마다 근거 글 링크) →
   holdout 검증(최근 글 빼놓고 "이 계기면 뭘 먼저 확인할까" 맞히기) 통과가 4단계 진입 조건.
4. **chat 주입**: 평소 = 통합 사고 지침을 PLAN(질문 분해·필요증거)·SYNTHESIZE에 주입.
   중요/불확실 질문(tier·DA 이중 블라인드 불일치가 기존 신호) = 블로거별 설계도 패널.
   주입 전후 같은 질문 세트 A/B.

## 실행 순서 (효용 빠른 순)

1. 분류 + 다이제스트 — 새 글 흐름부터 (매일 바로 체감)
2. 브리핑 피드 UI
3. 사고 기록 튜닝 루프 — 2~3명 소량, 탭에서 눈 검증
4. 백필(최신→과거) + 연쇄·설계도 + holdout 검증
5. chat 주입 + A/B

## 미확정 (사용자 결정 대기)

- 사고 추출 첫 대상: 제안 = 메르(ranto28, 사슬형 추론·2,468편으로 연쇄 가능) +
  체리형부(crush212121, 반도체 — 메모리 섹터 직결).
- 분석 모델 배치(분류=경량, 사고 기록=상위)의 구체 모델명 — 구현 시점 단가 확인 후 확정.
