# 토스 데이터 소스 품질 감사

- 실측일: 2026-07-21
- 범위: 토스 WTS 공개 read-only 데이터
- 원칙: 계좌·주문·로그인 우회 제외, 커뮤니티 원문/작성자 식별값 미저장

## 결론

토스만으로 시장 사실값 + 뉴스 전문 + 종목 수급 + AI/커뮤니티 심리를 결합할 수 있다.
단, 모든 소스를 같은 증거 등급으로 취급하면 안 된다.

| 등급 | 소스 | 사용법 |
|---|---|---|
| A — 사실값 | 공식 시세·차트·시장정보, WTS 재무지표·수급 | 숫자 주장과 계산의 직접 근거 |
| B — 기사 근거 | WTS 뉴스 피드·회사별 기사 전문 | 출처·시각을 보존해 주장 근거로 사용 |
| C — 보조 신호 | WTS AI 시그널 | 방향·이슈 후보로만 사용, 사후성과 검증 필수 |
| D — 집계 심리 | 커뮤니티 | 댓글 속도·고유 작성자·반응 집계만 사용, 사실 근거 금지 |

## 뉴스

- 인기 28, 주요 50, 최신 20, 급상승 4: 총 102회 노출.
- 고유 기사 94건, 둘 이상의 탭에 걸친 기사 8건, 최대 중복 2탭.
- 요약 길이 중앙값 300자, 빈 요약 0건.
- 실측 기사 시각 범위: 2026-07-21 03:36~16:00.

### 회사별 뉴스 본문

- 삼성전자·SK하이닉스 각 10건 표본.
- 수정 전에는 20/20건이 정확히 103자 프리뷰에 머물렀다.
- 원인: 상세 응답이 구형 `result.contentText`에서 `result.kr.content[]` 블록으로 변경.
- typed 계약과 추출기를 수정한 뒤 20/20건이 200자를 넘었고 본문 길이 중앙값은

판정: 뉴스는 Toss-only 리서치의 핵심 1차 재료다. 피드 중복 횟수는 중요도 신호로,
회사 뉴스 전문은 근거 텍스트로 사용한다.

## AI 시그널

- 게스트 대시보드 배치: 56~57종목, 고유 코드, 빈 사유 0건.
- 한 표본에서 국내 코드 25, 해외 코드 20, 나머지는 기타 내부 코드였다.
- 배치의 사유 길이는 중앙값 8자, 최대 11자로 매우 짧다.
- 개별 상세 12건 표본은 모두 200이며 생성시각·방향·`profitLossRate`가 존재했다.
- 방향은 positive 11 / negative 1로 한쪽에 치우쳤다.
- `reasoning.issue.description.data` 근거 배열은 12/12건 비어 있었다.
- 관련 사유 존재 플래그는 6/12건이었다.

판정: 빠른 이슈 탐지와 시장 심리 후보로는 좋지만, 현재 응답만으로는 “왜 맞는지”를
검증할 근거가 없다. 원자 사실로 승격하지 말고 생성시각의 가격을 고정한 뒤
1시간·1일·5일 forward return을 Toss 차트로 계산해 적중률을 검증한다.

## 랭킹·시장 컨텍스트

- 대시보드 랭킹 100종목/100고유 코드.
- 종목별 가격, 시가총액, 산업 분류, 토스증권 매수/매도 비율을 제공한다.
- 인텔리전스의 권장 polling interval은 실측 30초.
- 시장 지표 10개, 미국 주요 지표 6개, 경제 이벤트 11개와 AI 일정 요약이 확인됐다.

판정: 랭킹은 유니버스 생성과 관심도, 시장 지표·경제 이벤트는 보고서 배경축으로 바로
쓸 수 있다. 토스 매수/매도 비율은 시장 전체 수급이 아니라 토스 사용자 표본임을 라벨링한다.

## 커뮤니티

삼성전자·SK하이닉스 최신순 각 5페이지(55건) 표본:

| 지표 | 삼성전자 | SK하이닉스 |
|---|---:|---:|
| API totalCount | 1,631,363 | 1,425,760 |
| 표본 / 고유 작성자 | 55 / 49 | 55 / 49 |
| 메시지 길이 중앙값 | 21자 | 13자 |
| 빈 메시지 | 8 | 10 |
| 재게시 | 8 | 11 |
| 보유 표시 | 44 | 34 |
| 표본 시간폭 | 약 7분 | 약 7분 |

- 정렬 enum은 `POPULAR`과 `RECENT`.
- 응답 `key`는 마지막 `commentId`; 다음 페이지에 `lastCommentId`로 전달한다.
- 페이지당 11건이며 `size=50`은 실측상 적용되지 않았다.
- 댓글에는 닉네임, 프로필 ID/사진, 메시지, 보유상태, 좋아요·조회·답글이 포함된다.

판정: 활동 속도는 매우 높지만 메시지가 짧고 재게시·이미지형 빈 메시지가 섞인다.
작성자/원문을 보존하지 않고 분당 댓글 수, 고유 작성자 수, 보유 표시 비율, 반응률,
중복률만 시간 버킷으로 집계한다. 커뮤니티 문장은 사실 검증의 근거로 사용하지 않는다.

## 운영·계약 발견

- 직접 호출 가능한 공개 GET과 게스트 세션이 필요한 대시보드 POST를 분리해야 한다.
- 일부 POST는 `browser-tab-id`, `app-version`, `x-xsrf-token`이 없으면 400이고 공개
  WTS 게스트 세션에서는 200이다.
- 기존 뉴스 상세 파서는 스키마 변경을 조용히 삼켰다. “HTTP 200”만 확인하는 라이브
  테스트로는 부족하며 최소 내용 길이·필수 필드 비율을 함께 검사해야 한다.
- 비공개 WTS는 endpoint별 fixture와 typed schema, null 비율, 샘플 수 변화 알람이 필요하다.
